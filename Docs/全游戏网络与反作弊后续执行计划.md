# project10 全游戏网络与反作弊后续执行计划

## 一、项目方向

本项目后续不以 EOS 或 Steam 为基础，不接入账号登录，也不依赖第三方平台提供的 Session、身份认证或官方反作弊服务。当前开发和本机验证统一使用 Windows 版本；Linux Dedicated Server 适配放在全部 C++ 网络逻辑稳定之后。

目标方向是：

```text
腾讯云公网 Dedicated Server
    -> 客户端通过固定公网 IP 和端口连接
    -> 初期手动输入 IP，后续增加固定服务器连接按钮
    -> 服务器掌握所有真实玩法状态
    -> 客户端只发送输入和请求
    -> 服务器验证请求并复制结果
    -> 服务器记录异常行为并执行处理
```

这是一条可行路线，但必须明确它的边界：没有账号系统，就没有可靠的跨设备玩家身份；没有 EOS/Steam，就不能直接使用它们的 Session Ticket、账号封禁和官方客户端反作弊。后续反作弊应优先采用服务器端方案，客户端反作弊作为未来可选项，而不是当前主线阻塞项。

## 三、总体原则

### 1. 服务器权威优先

客户端不能决定以下内容：

```text
Health
Ammo
伤害
死亡
复活
击杀数
死亡数
当前武器
武器归属
玩家队伍
玩家位置的最终结果
回合状态
倒计时
```

客户端只能提交：

```text
移动输入
视角输入
开火请求
换弹请求
切枪请求
拾取请求
丢弃请求
复活请求
```

服务器验证请求后，才修改真实状态并复制给其他客户端。

### 2. 网络工程优先于反作弊

反作弊依赖可信的服务器数据。如果 Health、Ammo、命中和移动结果仍然由客户端决定，后续异常检测无法区分正常行为和作弊行为。

因此执行顺序必须是：

```text
Dedicated Server 基础
    -> RPC 和复制边界
    -> 服务器权威战斗
    -> 协议限流和参数校验
    -> 行为检测
    -> 证据和处罚
    -> 可选客户端反作弊
```

### 3. 表现和真实状态分离

`Multicast` 可以用于播放已经被服务器接受的表现，但不能作为真实状态来源。

允许放入 `Multicast`：

```text
动画
声音
粒子
枪口火焰
模型显示隐藏
UI 提示
```

禁止放入 `Multicast`：

```text
扣除弹药
修改 Health
计算伤害
决定死亡
增加击杀数
设置武器 Owner
决定当前武器
决定玩家队伍
```

### 目标

### 当前已具备的链路


### 必须解决的问题

- `StartRound` 当前仍在蓝图 `OnPostLogin` 链中。

- `Ending` 状态不能再启动空房计时器。
- Listen Server 不能同时执行 `ClientTravel` 和 `ServerTravel`。
- Dedicated Server 只能由服务器负责重新加载地图。
- Session 销毁成功、失败、超时只能最终跳转一次。

## 八、阶段 4：独立服务器反作弊

### 重要结论

在不使用 EOS/Steam 的前提下，不能直接完成 EOS Anti-Cheat 或 Steam 平台反作弊集成。这部分不应伪装成已完成，也不应该成为当前项目的阻塞点。

当前采用独立服务器反作弊：

```text
服务器权威
    -> 请求校验
    -> RPC 限流
    -> 行为统计
    -> 异常评分
    -> 证据保存
    -> 踢出或封禁
```

### 4.1 RPC 限流

每个玩家维护计数器：

```text
每秒开火请求数
每秒换弹请求数
每秒切枪请求数
每秒拾取请求数
每秒丢弃请求数
每秒复活请求数
每秒总 RPC 数
```

处理规则：

```text
超过软阈值：记录警告
超过硬阈值：丢弃请求
连续超过硬阈值：踢出本局
重复多局异常：进入人工封禁列表
```

所有阈值必须配置化，不直接写死在蓝图图表中。

### 4.2 射击异常检测

记录：

```text
服务器接受时间
客户端请求间隔
当前武器射速
实际弹药变化
命中次数
爆头次数
射线起点
射线方向
目标距离
遮挡结果
```

初步检测项目：

```text
射击间隔低于武器允许值
没有弹药却产生有效射击
死亡后仍产生有效射击
超出射程命中
没有视线却命中
短时间异常高命中率
短时间异常高爆头率
客户端请求方向与服务器角色朝向严重不一致
```

单项异常只能增加风险分，不能直接永久封禁。

### 4.3 移动异常检测

记录：

```text
服务器位置
服务器速度
服务器加速度
位置修正次数
空中时间
碰撞状态
传送或重生状态
```

检测项目：

```text
超过角色最大速度
超过合理加速度
短时间跨越不可达距离
无重生原因的位置跳变
穿过不可穿越碰撞体
持续忽略服务器位置修正
```

必须排除：

```text
重生
地图跳转
服务器延迟补偿
网络丢包后的合法位置修正
载具或特殊移动能力
```

### 4.4 证据系统

每次异常记录至少包含：

```text
服务器时间
本局 PlayerId
ConnectionId
服务器地址标识
地图
回合 ID
异常类型
异常数值
允许范围
最近 10 秒相关请求摘要
处罚结果
```

证据必须写入服务器日志，不能只写客户端日志。客户端可以被修改，服务器日志才是主要证据。

### 4.5 处罚体系

```text
Level 0：只记录
Level 1：限制异常请求
Level 2：踢出本局
Level 3：临时禁止该连接来源
Level 4：加入服务器本地封禁列表
```

由于没有账号系统，当前封禁只能基于以下信息：

```text
IP 地址
连接来源
服务器管理员提供的本地标识
当前连接身份
```

IP 封禁不能视为可靠账号封禁，因为 NAT、动态 IP 和多人共用网络都会造成误伤。正式处罚必须保留人工审核入口。

### 阶段完成标准

```text
异常 RPC 可以被服务器丢弃
异常射速可以被服务器识别
无限弹药请求不会改变服务器状态
非法移动会触发记录和位置修正
所有处罚都有服务器端证据
正常玩家单次异常不会永久封禁
同一异常连续出现时风险分会累计
日志中能关联玩家、连接、回合和异常类型
```

## 九、阶段 5：客户端完整性保护


### 当前方向的限制

不做账号登录意味着：

```text
PlayerId 只在当前连接或当前服务器进程内有效
无法可靠实现跨服务器账号封禁
IP 只能用于临时识别，不能等同于账号身份
```

不使用 EOS/Steam 意味着：

```text
不使用平台 Session 搜索
不使用平台账号 Ticket
不使用平台官方反作弊
服务器列表以后需要自建服务
```

## 十六、结论

独立 Dedicated Server、不做账号登录、不依赖 EOS/Steam，是可以执行的路线。

但路线应明确为：

```text
独立服务器网络安全方案
    != 第三方平台账号体系
    != 官方客户端反作弊
```

当前最优先的工作不是接入反作弊 SDK，而是让服务器真正掌握所有战斗结果，并对每个客户端请求进行验证。完成服务器权威、协议限流和行为日志后，即使没有账号系统，也能拦截大部分无限弹药、伪造射速、非法伤害、非法武器和异常移动问题。

账号认证、跨服务器封禁和高强度客户端作弊对抗属于当前方案无法完整提供的能力，必须在后续产品方向改变时重新评估。当前不以这些能力阻塞开发，先完成 Windows 环境下的 C++ 网络权威化和服务器端测试级反作弊，Linux 放在最后适配。

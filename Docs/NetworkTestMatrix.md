# Dedicated Server 网络测试矩阵

## 目的

本矩阵记录 UE5.8 多人技术演示的可复现 Dedicated Server 行为测试。M1 建立 LAN 基线；WAN、Lossy 和 Stress 配置属于 M4 工作，在 Dedicated Server 与服务端权威战斗里程碑通过前不得标记为已执行。

## 测试环境记录

每个测试与网络配置的组合都必须创建一条记录。

| 字段 | 必填内容 |
| :--- | :--- |
| 测试 ID | `T01` 至 `T08` |
| 结果 ID | 唯一标识，例如 `T01-LAN-001` |
| 提交 | 被测项目的 commit hash |
| 引擎 | 可用时记录 UE5.8 源码构建标识 |
| 地图 | `/Game/Maps/csgo` |
| 服务端命令 | 完整命令行 |
| 客户端命令 | 两个客户端的完整命令行 |
| 网络配置 | LAN、WAN、Lossy 或 Stress |
| 复现步骤 | 有顺序、可观察的操作 |
| 预期结果 | 预期的服务端权威状态 |
| 实际结果 | 实际观察到的行为 |
| 证据 | 相关服务端/客户端日志片段和抓取文件 |
| 结论 | Pass 或 Fail |
| 失败分析 | 适用时记录根因与修复提交 |

## 网络配置

| 配置 | 增加延迟 | 丢包率 | 所属里程碑 |
| :--- | ---: | ---: | :--- |
| LAN | 0 ms | 0% | M1、M2、M3 |
| WAN | 80 ms | 0% | M4 |
| Lossy | 150 ms | 2% | M4 |
| Stress | 250 ms | 5% | M4 |

网络模拟的具体实现方式在 M4 决定，并必须写入每条测试结果。不能将不同模拟方式产生的结果视为完全相同的测试运行。

## 核心测试用例

| ID | 场景 | 预期的服务端权威结果 |
| :--- | :--- | :--- |
| T01 | 启动服务端并加入两个客户端 | 两个客户端均获得有效的 PlayerState 和 Pawn；没有非预期断线 |
| T02 | 装备、切换、丢弃和拾取武器 | 服务器拥有每个装备状态切换；每把掉落武器只有一份一致状态 |
| T03 | 快速连续开火 | 服务器强制射速和弹药状态；客户端不能制造额外的有效射击 |
| T04 | 伤害、死亡、得分和复活 | 服务器为所有客户端产生一致的生命、死亡、得分和复活结果 |
| T05 | 持枪死亡 | 一把权威掉落武器以一致状态可见且可交互 |
| T06 | 比赛进行中晚加入 | 新加入客户端获得正确的玩家、得分、比赛、已装备武器和掉落武器状态 |
| T07 | 断开并重连 | 服务器清理玩家状态，重连路径稳定 |
| T08 | 比赛结束、空房间重置和跳图 | 服务器只执行一次重置或跳图，不产生重复切换 |

## 执行顺序

1. Windows Dedicated Server 能启动 `csgo` 且两个独立客户端可加入后，立即在 LAN 下执行 T01 至 T08。
2. 每次影响对应场景的服务端权威战斗改动后，重复完整 LAN 矩阵。
3. M3 通过后，在 WAN、Lossy 和 Stress 下执行全部八项测试。
4. M4 验收集包含 32 条结果：八项测试乘以四种网络配置。

## M1 验收记录

M1 通过前，必须记录一次至少十分钟的 LAN 会话：两个独立客户端连接 Windows Dedicated Server。记录必须证明服务端在无编辑器 UI 的情况下启动，两个客户端都加入 `csgo`，且没有 Fatal、ensure、崩溃或非预期断线。

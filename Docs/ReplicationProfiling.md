# 复制性能分析契约

## 目的

本文定义修改复制频率、相关性或 Dormancy 前必须获得的证据。性能分析与优化放在 Windows C++ 服务端权威战斗稳定之后。本次文档工作不修改任何当前 `NetUpdateFrequency`、相关性或 Dormancy 设置。

## 范围

当前先在 Windows 环境建立基线，最终采集两个独立 Windows 客户端连接 Windows Dedicated Server 时的行为。在 C++ 服务端权威战斗切片通过后、任何优化被视为完成前，重复核心采集。Linux Dedicated Server 适配完成后，再单独采集 Linux 数据，不能把 Windows 和 Linux 的结果混为一组。

当前部署方向：

```text
本机 Windows 开发
    -> Windows Dedicated Server 打包
    -> 腾讯云固定公网 IP 验证
    -> Linux Dedicated Server 最后适配
```

分析以下 Actor 组：

| Actor 组 | 需要回答的问题 |
| :--- | :--- |
| 角色 | 移动、战斗、死亡和复活时，有多少 Actor 复制、以何种频率复制、占用多少带宽？ |
| 已装备武器 | 已挂接武器是否向无关客户端发送不必要的 Transform 更新？ |
| 掉落武器 | 移动期间是否一致复制，落稳后是否进入 Dormancy？ |
| PlayerState | 公开身份、队伍和得分变化是否仅在需要时复制？ |
| GameState | 计时和比赛状态更新是否正确且数据量合理？ |

## 必需证据

每次采集记录以下内容：

| 字段 | 必填内容 |
| :--- | :--- |
| 提交与引擎构建 | 精确的被测版本 |
| 服务端与客户端命令 | 完整命令行 |
| 地图与场景 | 包含测试 ID 或精确的脚本化步骤 |
| 网络配置 | LAN、WAN、Lossy 或 Stress |
| 采集方式 | `stat net`、Unreal Insights、CSV profiling、Network Profiler 或其他指定 Unreal 工具 |
| 时长 | 开始/结束时间和总时长 |
| 服务端帧时间 | 平均值和 P95 |
| 服务端内存 | 开始、峰值、结束和趋势 |
| 出站带宽 | 总量；可用时按 Actor 类分组 |
| 复制行为 | 相关 Actor 数量与更新频率 |
| 产物路径 | 已保存 trace、CSV、Profiler 抓取或日志位置 |

## 采集集

| 采集 ID | 场景 | 最低观察内容 |
| :--- | :--- | :--- |
| P01 | 两个客户端加入后静止 | Actor 数量、带宽和更新频率基线 |
| P02 | 移动与装备/切换武器 | 角色和已装备武器的复制行为 |
| P03 | 连续开火、伤害、死亡和复活 | 战斗状态带宽与复制正确性 |
| P04 | 丢弃武器并等待其落稳 | 掉落武器在落稳前后的更新行为 |
| P05 | 存在活动玩家和掉落武器时晚加入 | 新加入客户端的初始复制正确性 |
| P06 | 两客户端运行三十分钟 | 服务端帧时间、内存趋势、断线、Fatal 和 ensure |

## 优化决策规则

不能仅因 Actor 当前使用 `NetUpdateFrequency=100` 就进行优化。必须先采集证据，再进行一项有边界的改动，并重复相关采集集。

| 候选改动 | 验收前所需证明 |
| :--- | :--- |
| 降低闲置更新频率 | 开火、伤害、死亡、复活、晚加入和快速武器切换均无回归 |
| 对掉落武器应用 Dormancy | 晚加入、拾取、丢弃和落稳后的移动状态均正确 |
| 限制已装备武器的相关性或 Transform 复制 | Owner 与观察者均保持正确的挂接、切换、丢弃和死亡表现 |
| 修改 Actor 相关性 | 所有应当观察该武器或角色的客户端持续获得其权威状态 |

每一项通过的优化都必须使用相同地图、场景、客户端数量、网络配置和采集方式进行前后对比。
